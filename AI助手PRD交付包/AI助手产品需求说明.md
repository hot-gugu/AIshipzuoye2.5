# AI 助手产品需求说明

> 文档版本：V1.0  
> 适用版本：无视频不作业系统 2.3  
> 一期范围：作业计划、AI 违章/隐患预警、违章/隐患查处、实时监控、视频倒查  
> 文档状态：研发与测试交底版

## 1. 建设背景

现有系统已经形成作业计划、摄像头、实时监控、视频回传、AI 预警、违章查处、隐患整改等业务数据，但用户仍需进入多个菜单、设置筛选条件并人工汇总。AI 助手以自然语言作为统一入口，帮助用户完成数据查询、统计看数、待办定位和业务导航。

一期助手只读取业务数据并生成受控页面跳转，不在对话中执行查处、复核、整改、编辑、删除等写操作。所有业务数值必须来自业务后端返回的结构化结果，大模型不得自行推算未定义指标。

## 2. 产品目标与验收指标

### 2.1 产品目标

1. 用户无需理解菜单结构和字段名称即可查询授权范围内的业务数据。
2. 对数量、占比和分组统计使用统一指标口径，答案可追溯。
3. 将待办事项精确定位到业务记录，并通过按钮进入原业务流程。
4. 支持多轮修改时间、单位、状态等条件，减少重复输入。
5. 严格继承组织、数据、字段、页面和操作权限，杜绝越权泄露。

### 2.2 一期验收基线

| 指标 | 标准 |
|---|---|
| 核心指标计算准确率 | 100% |
| 跳转动作及业务 ID 正确率 | 100% |
| 权限越权事件 | 0 |
| 规定意图识别成功率 | ≥90% |
| 关键参数抽取准确率 | ≥95% |
| 普通查询响应时间 | P95 ≤5 秒 |
| 复杂分组统计响应时间 | P95 ≤10 秒 |
| 可追溯性 | 每个数据答案均包含指标编码、查询条件、实际权限范围和数据更新时间 |

## 3. 用户角色

| 角色 | 典型诉求 | 权限原则 |
|---|---|---|
| 集团/公司管理人员 | 查看授权组织整体作业、预警及闭环情况 | 授权本级及下级组织，只展示获授权字段 |
| 安全管理人员 | 查询待复核、待查处、待整改事项并进入处理页 | 数据范围与业务岗位授权交集；动作受状态和按钮权限控制 |
| 生产管理人员 | 查看作业计划、视频回传、监控关联情况 | 仅限其生产组织和获授权作业 |
| 监控中心人员 | 查看摄像头在线、实时预警及作业监控 | 需监控页面权限和摄像头数据权限 |
| 普通业务人员 | 查询与本人或本部门相关的数据 | 仅本人/本部门授权范围，敏感字段脱敏 |
| 系统管理员 | 配置权限、查看审计，不默认获得全部业务数据 | 管理权限与业务数据权限分离 |

## 4. 一期范围

### 4.1 支持能力

- 作业计划：数量、列表、危险作业、未回传作业、详情及监控/倒查导航。
- AI 预警：违章/隐患预警数量，按单位、等级、来源、复核状态统计，待复核列表及复核导航。
- 违章查处：有效违章、误报、待查处、已处理列表及查处导航。
- 隐患查处：待整改、整改中、待验收、已闭环列表及整改导航。
- 实时监控：在线/离线摄像头、关联作业情况、实时预警及页面导航。
- 视频倒查：应回传、已回传、未回传、回传完成率、可倒查作业及页面导航。
- 多轮条件继承、条件修改、条件清空、历史会话恢复。

### 4.2 不支持能力

- 不在对话中直接查处、复核、整改、删除、编辑、创建计划或上传视频。
- 不支持语音输入、主动推送、跨系统写操作和开放式数据库查询。
- 不支持未登记在指标字典中的临时计算公式。
- 不输出用户无权查看的组织名称、记录数量、敏感字段或动作入口。

## 5. 产品入口与信息架构

### 5.1 全局入口

- 在所有登录后业务页面右下角展示“AI 助手”悬浮入口，距右、下边缘 24px。
- 入口受功能开关和 `assistant.access` 页面权限控制；无权限时不显示。
- 点击后从右侧打开宽 420px 的抽屉；页面宽度不足 768px 时使用全屏抽屉。
- 抽屉关闭不清空会话。再次打开时恢复最后一轮内容和滚动位置。
- 入口存在未读系统提示时显示角标；一期不做业务主动推送。

### 5.2 抽屉结构

1. 标题栏：AI 助手、历史会话、清空上下文、关闭。
2. 上下文栏：当前页面、时间、组织、状态等已生效条件标签；标签可删除。
3. 消息区：用户消息、助手答案、加载/停止、错误及重试。
4. 推荐区：首次使用或空会话时展示 4—6 个推荐问题。
5. 输入区：多行输入框、发送按钮；Enter 发送，Shift+Enter 换行。
6. 页脚提示：“回答仅基于您有权访问的系统数据”。

### 5.3 历史会话

- 默认保存最近 30 个会话、每个会话最近 100 条消息，保存 90 天；期限可配置。
- 会话标题由首个成功意图生成，用户可重命名和删除。
- 恢复会话时同时恢复业务对象、时间、组织、状态和分页上下文；权限发生变化后必须重新鉴权。
- “清空上下文”仅清除当前对话继承条件，不删除历史消息；需要二次确认。

## 6. 上下文与条件规则

### 6.1 公共条件

| 条件 | 说明 | 优先级 |
|---|---|---|
| 业务对象 | 作业、预警、违章、隐患、摄像头等唯一 ID | 最高 |
| 时间范围 | 开始时间、结束时间、时区 Asia/Shanghai | 显式输入优先 |
| 组织范围 | 组织 ID 列表；最终与授权范围取交集 | 显式输入优先 |
| 状态 | 业务状态编码，不使用显示名称作为查询值 | 显式输入优先 |
| 分类/等级/来源 | 使用字典编码 | 显式输入优先 |
| 排序和分页 | 默认发生时间倒序、第一页 10 条 | 最低 |

### 6.2 条件优先级

`本轮显式条件 > 上轮会话条件 > 当前页面对象上下文 > 产品默认值`。

- 新问题默认继承上一轮相同业务域的时间、组织和状态。
- 用户切换业务域时只继承组织；时间按新意图默认规则重新计算。
- 用户说“清空条件”“重新查询”后，清除继承条件并使用产品默认值。
- 所有相对日期由业务后端按服务器时间和用户时区转换为绝对起止时间并回显。

### 6.3 默认值

- 作业、实时预警、摄像头在线问题未指定时间：今天 00:00:00 至查询时刻。
- 待办、待查处、待复核、待整改：查询瞬间的当前状态，不加历史状态快照。
- 未指定组织：当前用户全部授权组织。
- 列表：发生/计划开始时间倒序，10 条/页。
- 统计：只返回有数据且有权展示的分组；总计不得包含无权组织。

### 6.4 必须澄清的场景

- 同名单位、人员、作业或摄像头匹配到多个对象。
- “这个作业”“该预警”等指代在上下文中无法唯一确定。
- 用户给出的开始时间晚于结束时间，或条件互相冲突。
- 请求的统计对象或口径不存在对应指标编码。
- 用户要求跳转，但列表中存在多个可操作对象且未指定目标。

澄清问题应给出不超过 5 个候选项，展示能够区分对象的单位、时间、位置等字段，用户选择后保存唯一 ID。

## 7. 核心业务场景

### 7.1 数据查询

示例：“今天有多少作业？”

1. AI 识别 `work_plan.count`，提取今天和组织条件。
2. 业务后端将组织条件与用户授权组织取交集。
3. 调用 `query_metric` 查询 `WORK_PLAN_COUNT`。
4. 返回单指标卡片：数量、时间范围、组织范围、指标口径、数据更新时间。
5. 卡片提供“查看作业列表”；点击调用 `resolve_navigation` 生成受控链接。

作业计划数口径：计划开始时间至计划结束时间与查询区间存在交集，状态不为作废/已删除，按作业计划业务 ID 去重。

### 7.2 分组统计

示例：“统计近 7 天违章预警，分别是哪些单位？”

1. 识别 `warning.violation.group_by_org`，时间为近 7 个自然日（含今天）。
2. 调用 `query_metric`，指标 `VIOLATION_WARNING_COUNT`，维度 `org_id`。
3. 结果按数量降序；返回总计、分组表和横向条形图。
4. 分组之和必须等于同权限、同条件下总计；否则结果标为不可用并提示数据服务异常。
5. 用户追问“只看齐大山选矿厂”时继承时间和指标，只替换组织条件。

### 7.3 待办事项

示例：“我有哪些待查处违章？”

1. 识别 `violation.pending_handle.list`。
2. 调用 `list_business_items`，状态为 `PENDING_HANDLE`，处理人/岗位为当前用户可处理范围。
3. 展示总数和事项卡片：违章名称、等级、单位、地点、发生时间、状态。
4. 每条记录根据后端 `allowed_actions` 显示“查看详情”或“去查处”。
5. 点击“去查处”前调用 `resolve_navigation`；目标页再次鉴权并刷新状态。
6. 若事项已处理，提示“事项已处理或不存在”，刷新当前列表，不打开其他记录。

### 7.4 业务对象详情

- 用户点击事项名称或问“第 2 条详情”时调用 `get_business_detail`。
- 详情卡只展示字段权限允许的字段；手机号、身份证等继续脱敏。
- 详情返回对象 ID、对象类型、状态版本号和允许动作。
- 状态发生变化时以最新结果为准，并提示“数据已于 HH:mm 更新”。

### 7.5 实时监控

- 可查询在线、离线摄像头数，以及摄像头是否关联作业。
- “查看这个作业的监控”需唯一作业 ID；跳转实时监控页的“作业计划”Tab，并筛选该作业。
- 目标页面提供“查看全部作业”和返回助手来源页能力。
- 助手不直接拉取或播放视频流，不展示未授权摄像头名称。

### 7.6 视频倒查

- 查询应回传、已回传、未回传作业和完成率。
- 视频回传完成率=`已回传作业数 / 应回传作业数 × 100%`；分母为 0 时展示“--”，不得展示 0%。
- “视频倒查”跳转按作业计划倒查页并携带作业 ID；目标页默认只展示该作业，可取消过滤。
- 是否可倒查由业务后端根据回传状态、保存期限和页面权限决定。

## 8. 回答展示规范

### 8.1 公共元信息

所有数据答案底部固定展示：

- 时间范围（绝对时间）；
- 实际查询组织范围；
- 指标名称和指标编码；
- 数据更新时间；
- 数据来源模块；
- “查看口径”入口。

### 8.2 结果组件

| 组件 | 使用场景 | 必须字段 |
|---|---|---|
| 单指标卡 | 单个数量、比例 | 指标名、值、单位、口径编码、时间/组织标签 |
| 分组统计表/图 | 按单位、等级、来源、状态统计 | 分组名、数值、占比、合计、排序 |
| 事项列表 | 待办、作业、预警列表 | 对象 ID、主标题、关键字段、状态、允许动作 |
| 详情卡 | 单个业务对象 | 对象类型、唯一 ID、状态、字段列表、允许动作 |
| 导航按钮 | 进入业务页面 | 动作编码、按钮名、目标对象 ID |
| 口径说明 | 数值回答 | 指标编码、定义、公式、时间字段、排除项 |

图表只是结构化结果的可视化，不得对后端结果二次聚合或改变精度。表格默认最多展示 10 行，提供“查看更多”。

## 9. 异常与边界处理

| 场景 | 交互 |
|---|---|
| 真实结果为 0 | “在【时间】【组织】范围内，指标结果为 0”，仍展示口径 |
| 数据为空/未同步 | “暂无可用数据”，说明数据源和最近更新时间；不得表述为 0 |
| 无数据权限 | “你没有该范围的数据访问权限”；不暴露真实数量和组织名称 |
| 无动作权限 | 保留可见数据，隐藏动作按钮，并标注“无××权限” |
| 参数冲突 | 指出冲突条件并要求用户修正 |
| 同名对象 | 展示候选项要求选择，不猜测 |
| 查询服务失败 | 明确提示查询失败并提供重试；禁止模型估算 |
| 超时 | 10 秒后提示超时，可停止或重试；后端取消无用查询 |
| 数据状态变化 | 刷新后提示最新状态，移除失效动作 |
| 跳转目标不存在 | “事项已处理或不存在”，留在助手并刷新列表 |

## 10. 受控 AI 工具接口

### 10.1 通用请求头

- `conversation_id`、`message_id`、`user_id`、`tenant_id`；
- 登录令牌由网关透传，不允许模型生成或修改；
- `timezone=Asia/Shanghai`、`locale=zh-CN`；
- `trace_id` 用于全链路审计。

### 10.2 `query_metric`

用途：查询单指标或分组统计。

```json
{
  "metric_code": "VIOLATION_WARNING_COUNT",
  "time_range": {"start": "2026-08-18T00:00:00+08:00", "end": "2026-08-24T23:59:59+08:00"},
  "organization_ids": ["ORG-001"],
  "filters": {"review_status": ["PENDING"]},
  "group_by": ["org_id"],
  "order_by": [{"field": "value", "direction": "desc"}]
}
```

返回必须包含：`metric_code`、`metric_name`、`value/rows`、`unit`、`actual_scope`、`query_conditions`、`data_time`、`source_service`、`quality_status`。

### 10.3 `list_business_items`

用途：查询作业、预警、违章、隐患、摄像头等列表。

请求必须包含：`object_type`、时间、组织、过滤条件、排序、页码、每页条数。返回每条记录必须包含业务唯一 ID、展示字段、状态编码、状态版本、`allowed_actions`。

### 10.4 `get_business_detail`

用途：读取单一业务对象详情。请求仅允许 `object_type + object_id`，不得用名称直接读取。返回字段须经过字段权限和脱敏处理。

### 10.5 `resolve_navigation`

用途：按对象和动作生成合规跳转信息。

请求：`action_code`、`object_type`、`object_id`、`source_page`、`return_url`。返回：目标页、参数、默认 Tab、有效期、动作可用性及不可用原因。跳转令牌短期有效且绑定当前用户，目标页必须二次校验。

## 11. 指标与数据规则

- 指标定义以《AI助手指标口径与字段字典.xlsx》为唯一产品基线。
- AI 只引用指标编码，不得提交自由 SQL、数据库表名或计算表达式。
- 计数按业务唯一 ID 去重；逻辑删除、作废和撤销数据按各指标规则排除。
- 相对日期转换、组织权限过滤、状态映射和数值计算均在业务后端完成。
- 分组统计返回服务端合计；前端只做显示校验。
- 空值、重复、延迟和异常数据按指标字典处理，并返回 `quality_status`。

## 12. 权限、安全与审计

### 12.1 权限执行顺序

1. 页面/助手访问权限；
2. 租户隔离；
3. 组织数据范围；
4. 对象数据权限；
5. 字段权限与脱敏；
6. 动作权限；
7. 业务状态是否允许动作。

未指定单位时，使用用户全部授权组织；显式指定时与授权范围取交集。无权组织不能出现在明细、分组、总计、候选项或自然语言解释中。

### 12.2 敏感信息

- 手机号默认显示前 3 后 4 位；身份证显示前 6 后 4 位；无字段权限则完全不返回。
- 截图、视频和流地址只通过短期鉴权 URL 使用，助手不回显真实存储地址或 RTSP 地址。
- 用户问题中包含敏感信息时，日志保存脱敏副本；原文按安全策略加密并限制访问。

### 12.3 审计日志

记录：用户、租户、会话、原始问题脱敏文本、识别意图、解析条件、指标编码、实际权限范围、调用工具、返回对象 ID、数据更新时间、耗时、异常、用户点击动作及目标页面。日志保留期由安全策略配置，默认 180 天。

## 13. 业务跳转规范

- 所有跳转使用业务唯一 ID，不得依赖名称定位。
- URL/路由必须携带 `source=assistant`、会话 ID 和编码后的返回地址。
- 目标页面按 ID 加载记录并再次校验数据、字段、页面、按钮权限和业务状态。
- 返回助手时恢复原页面、原会话、滚动位置及查询条件。
- 详细映射以《AI助手业务跳转映射表.xlsx》为准。

## 14. 团队职责边界

| 团队 | 负责 | 不负责 |
|---|---|---|
| 产品经理 | PRD、意图清单、指标口径、跳转、权限、原型、验收标准 | 技术模型选型、接口实现 |
| 传统业务研发 | 结构化查询、指标计算、权限校验、详情、跳转、前端抽屉、审计 | 自然语言理解和答案生成 |
| AI 研发中心 | 意图识别、参数抽取、上下文、澄清、受控工具调用、答案编排、评测 | 直接访问业务库、定义业务口径、绕过权限 |
| 测试团队 | 功能、口径、权限、跳转、异常、性能、回归和评测集执行 | 修改产品口径 |
| 运维/安全 | 网关、密钥、日志、监控、限流、数据安全 | 业务验收结论 |

## 15. 非功能要求

- 可用性：核心查询服务月可用性 ≥99.9%。
- 性能：普通查询 P95≤5 秒，复杂统计 P95≤10 秒；前端 300ms 内展示加载状态。
- 并发：按生产容量评估，查询接口支持限流、熔断、超时和取消。
- 一致性：展示数据更新时间；实时数据允许按源系统更新周期存在可解释延迟。
- 可观测性：每次对话产生 trace_id，可串联模型、工具、权限和页面跳转日志。
- 可访问性：键盘可操作、焦点可见、状态不只依赖颜色表达。

## 16. 上线与灰度

1. 使用测试组织和脱敏数据完成指标、权限、跳转验收。
2. 内部安全管理人员灰度，观察意图失败、无数据、超时和误跳转率。
3. 按组织开启功能开关；出现越权、错误口径或高错误率时可即时关闭。
4. 上线后按周复盘未识别问法、澄清率、任务完成率和人工纠错记录，更新评测集。

## 17. 验收规则

- 标准答案以《AI助手验收用例与评测集.xlsx》为准。
- 指标值必须与同条件业务接口或数据库核验结果完全一致。
- 分组之和、总计、占比和完成率公式必须通过自动化校验。
- 对无权限组织、字段和动作执行反向越权测试。
- 所有跳转逐条验证目标对象、默认 Tab、返回地址和状态变化。
- 模型无法确定意图或对象时必须澄清；查询失败时不得生成推测数字。
